## 三、操作与后端放行

1. 销售选授权客户、商品和配送及运费责任，确认后生成金额版本；有超权折扣时交老板审批。管理员调价时新增快照，旧版本保留。已发生出库后的变更进入后续售后。
2. 门店付款材料登记时无账务影响。财务对银行账单确认实到，或核对现金交接后批准实收。差额通过新付款、退款或获批更正处理，禁止用超付直接充当收入。涉及已有旧版实收的订单，当前版本须额外经财务核对。
3. 仓库按分配范围从合格批次预留。通过扣减实物和释放预留的独立流量记录出库。履约状态顺序为公司或第三方先出库、再发运、再交付；自提在授权仓库一次完成出库和交接。
4. 所有履约分支进入 `server/trade-fulfillment.mjs` 的统一检查，由安全 API 在 SQLite `BEGIN IMMEDIATE` 事务内执行。检查会话、角色与订单/仓库/配送范围、订单状态、当前版本、核实净额、未结付款和退款、批次及库存、应有的上一步与重复动作。失败事务回滚。原沙盒模拟路由在安全入口返回 404。
5. 已出库订单禁止走普通取消、冲销或退款入口，以免改变真实交付的历史。待处理退款会阻止尚未执行的出库。出库与退款并发测试只允许一方成功。

| 销售经理 | 身份会话；区域经营审批待 CRM 权限接入 |

| 仓库 | 指定仓库订单、预留异常及受控出库、发运、自提 |
| 配送 | 指派订单及签收 |

## 五、演示、恢复和下一阶段

在独立仓库执行 `npm.cmd run demo:trade`，打开 `http://localhost:4311/trade`。以终端打印的随机虚构账号登录。用销售账号添加两种商品，选配送及运费承担、建单和预留，填测试银行参考号登记付款；退出后以财务账号核实并确认到账，仓库账号出库，最后以老板账号查看审计。金额输入使用最小货币单位。Edge 自动化已实际完成上述顺序。演示服务在验证结束后关闭，需用命令启动。可运行 `npm.cmd run test:trade:browser` 重验。

回滚原则为固定代码版本和迁移版本，将一致性 SQLite 快照先恢复到独立目录，验证哈希、外键、金额、流水及历史后才允许切回。已有新到账、退款或库存变更时先停写留存新库，按差异对账、回放或前向修复。正式 PostgreSQL 迁移、备份保留制度、生产 TLS、实际财务口径、区域权限、大规模并发与移动真机均未验证。
