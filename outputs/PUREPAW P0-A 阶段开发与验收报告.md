## 3. 实现与本地复核

- 演示通过开发仓库 `npm.cmd start` 启动，默认地址 http://127.0.0.1:4310，数据默认写入该仓库的 `.local/purepaw.sqlite`。安全预览按 README 初始化独立管理员后运行 `npm.cmd run start:security`，运行于 localhost:4311，身份库为 `.security-preview/identity.sqlite`，不种入演示账号或业务数据。开发仓库提交后两类运行库目录均不存在；自动化套件使用随机临时目录，启动冒烟使用独立源码归档副本。
- 身份以账号密码核实，异步 scrypt、随机盐、短时随机会话与单向会话哈希。浏览器 Cookie 设置 Secure、HttpOnly、SameSite=Strict。客户端角色参数不能改变服务器保存的账号角色。管理员初始化只能从本机管道为身份空库创建一次首个管理员。
- 安全预览后端对创建账号、停用及审计读取作显式权限检查。停用和删除所有会话在同一事务执行，重复停用不会重复写事件。记录关键操作人、时间、前后值、原因和请求标识，应用层与 SQLite 触发器限制审计改删。
- 模拟收款及履约留在原沙盒，原来允许销售操作 pay、ship、deliver 的风险仅限该入口和虚构环境。安全预览对模拟登录、模拟社交、付款、发运及交付均返回 404；测试覆盖管理员、销售、匿名和演示 Cookie。两种入口在 NODE_ENV=production 均拒绝启动。后续任何业务路由接入前必须先通过交易安全验收。
- 身份迁移独立于旧 SQLite。启动在同一事务核验 schema_migrations 顺序及 SQL SHA-256，再执行未应用迁移。遇未知/已修改版本或无版本的非空库拒绝打开。P0-A 不执行旧库转换。回滚使用同版本源码和已验证一致性快照；后续涉及正式流水时先停写、保存新流水并对账，再回放或向前修复。

尚需确认权威远端或最新源码、旧数据处理范围、正式收款授权及岗位交接、财务制度、含税及单据、退货期限、会计确认口径、数据存放与合规。预览未接浏览器登录 UI、MFA、密码恢复、生产 TLS、跨实例限流、正式审计外部保全或生产灾备。管理级 SQLite 文件访问仍能绕过应用审计策略。财务和仓储权限目前只作为权限矩阵能力，统一交易放行未实现。原模拟版本只应用于本机虚构数据演示。

P0-B 获批后按以下顺序执行：

1. 订单及金额。建立多行成交价与规格快照、整数金额、折扣权限及审批；新增运费预估、客户约定、实际支出、分摊与变更版本。分摊需守恒，已付的应收不得被物流成本自动调高。
2. 收款流水。区分现金实收、银行实到和凭证，费用与多笔付款可对账。授权核实、重复凭证或流水识别、差额审批、冲销与退款。订单创建、付款登记和核实使用稳定幂等键。
3. 库存预留。实现分仓维度与批次锁，在事务中建立预留与流水。初始 24 小时可配置；已全额付款到期进入异常，保留预留。并发竞争可售库存时至多一方获得可用量。
4. 统一履约门禁。让出库、发运、交付和自提共用服务端检查，锁定订单和相关库存，验证有效订单、足额实收、无未结差额、效期和库存、权限与任务范围。同步测试三种方式、部分付款、截图、重复请求、已付但库存不足及付款冲销竞态。具体签收与售后在对应阶段完成。
5. 提交迁移与回滚脚本、财务/库存对账证据、演示和自动化报告。实交易与必要批次、配送、售后能力验收完成前保持本地虚构数据运行。
