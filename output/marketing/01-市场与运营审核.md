## 调研计划与品牌方资料

1. 从 Uzum、当地零售站点、当地门店采集至少 30 条在架记录。优先补 Pro Plan、Felix、Sheba、Pedigree、Club 4 Paws 与 Nutrimax。对照猫／犬、干／湿、年龄、原厂包装／散装、规格和促销，留原价、现价、库存、配送区、采集时点及链接或价签照片。
2. 计划征集 5 家门店的书面进货条件。统一询问起订量、阶梯价、税费、账期、近效期退换、配送范围、样品和首单条件。本轮仅建名单。
3. 计划对可访问的商品页按最近排序采集最多 50 条买家评价，记录 SKU、日期、来源、平台显示的已购标识及主题。若不足则报告实际样本量；去重并分别统计适口性、包装、物流和价格。竞品社媒按最近 30 天记录频次、形式、语言、行动引导及公开互动。
4. 定价阶段按同物种、生命周期、产品形态和匹配规格比价，同时记录袋价、公斤价。PUREPAW 的零售建议价与批发底价须用成本、渠道毛利与履约预算验证。

## 官方发布路径与任务队列

五个平台现状均为**授权待核验，仅建待发布任务**。实际授权验证需由账号管理员提供资产与权限证据。测试和公开发布分别取得明确批准。

| 平台 | 官方路径与核验 |
|---|---|
| Instagram | 专业账号通过 Content Publishing 创建媒体容器、检查处理状态、执行发布。Instagram Login 核对 `instagram_business_basic`、`instagram_business_content_publish`。Facebook Login 路径核对关联主页、适用权限和素材访问方式。[Meta Content Publishing](https://developers.facebook.com/documentation/instagram-platform/content-publishing) |
| Facebook | Page Feed 校验正确主页及 Page token、CREATE_CONTENT、`pages_manage_posts`、`pages_read_engagement`、`pages_show_list`。视频版进入测试前另核所在应用的 Page Reels 发布能力。[Meta Page Feed](https://developers.facebook.com/docs/graph-api/reference/page/feed/) |
| Telegram | Bot API 校验 bot 身份、目标频道及频道管理员 `can_post_messages`。选 `sendMessage` 或 `sendVideo`。测试用独立私有频道。[Telegram Bot API](https://core.telegram.org/bots/api) |
| YouTube | Data API `videos.insert` 与 OAuth `youtube.upload`，核对频道、项目限制和上传权限。测试显式设置 `private`，不填 `publishAt`。[YouTube 上传](https://developers.google.com/youtube/data/reference/rest/v3/videos/insert) · [隐私字段](https://developers.google.com/youtube/data/reference/rest/v3/videos) |
| X | 开发者项目与应用、具有写权限的用户授权，含视频时先核验 Media Upload，再调用 `POST /2/tweets`。确认额度和费用设置后才进入经批准的测试。[X 创建帖子](https://docs.x.com/x-api/posts/create-post) |

统一内容库存于同目录的首周内容文件。渠道任务引用内容 ID 和版本。状态使用草稿、待审核、已批准、已发布、失败。待发布任务记录渠道、目标账号、渠道版文案、素材 ID、时区、授权状态、原因和审批记录。批准绑定内容版本、素材、渠道及测试或公开的范围，任何变更须回到待审核。平台确认回执后登记发布 ID 和链接。超时先查平台回执，再决定是否重试。人工发布同样需要批准并回填结果。

## 销售台账与 Qoder 交接

曝光 → 私信咨询 → 产品推荐 → 报价 → 订单 → 付款 → 配送 → 复购。内容标记渠道和内容 ID，首次咨询建立客户 ID，报价关联 SKU、价格版本与库存，付款关联订单 ID，经履约确认后跟进。每天按塔什干自然日汇总。

| 指标 | 每日口径 |
|---|---|
| 视频数、曝光量 | 按确认发布的渠道帖子 ID 计数；曝光和播放按平台口径分列，同一人的跨平台触达无法去重。 |
| 客户咨询数、有效线索 | 首次有效对话按客户 ID 去重。有效线索指目标服务区、有明确宠物需求且同意后续联系的客户。B2B 单列。 |
| 订单、销售额、退款 | 按订单 ID 分记创建、实付、退款、已送达。销售额报告实付总额、退款与净额。 |
| 广告花费、每笔获客成本 | 按获批活动归因。CAC＝广告费 ÷ 可归因的首购实付客户数。分母为零填“—”。 |
| 宠物店开发及意向 | 去重门店数，分为已联系、索要资料、有书面试单或采购意向。 |
| 老客复购 | 当天再次实付的去重客户数、复购订单与金额。另按首购月份跟踪 30 天复购率，完整观察期的首购客户作分母。 |

供 Qoder 评审的测试环境契约为 `GET /channels/{id}/capabilities` 返回账号、允许的动作、核验时间与失败原因；`POST /publication-tasks` 保存内容版本及测试／公开目标；`POST /publication-tasks/{id}/approval` 记录审批人、范围和版本；`POST /publication-tasks/{id}/execute` 仅在权限与审批匹配时消费任务；`POST /sales-events` 写入事件 ID、时间、渠道、内容、客户或订单 ID。每个发布任务用渠道、账号和任务 ID 做幂等控制。用假账号和假订单验收无审批、版本改动、权限撤销、重复执行、平台超时和回执对账。营销侧提供脚本、素材、审核与验收口径，Qoder 负责实现。此次交付仅写营销文档。
