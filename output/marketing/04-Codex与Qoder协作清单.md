# PUREPAW Codex 与 Qoder 协作清单

2026-11-20，待审核。依据为 Qoder [API 文档](../mvp/README.md#本地-api-与演示数据)、[当前实现](../mvp/server/app.mjs)及[浏览器验收报告](../qa-runtime/中文验收报告.md)。此前营销文档中的示意 API 仅供规划，本清单以实际接口为准。

## 分工

| 负责人 | 交付与验收 |
|---|---|
| Codex／营销 | 编号、文案、字幕、素材、版本、依据、目标渠道、转化指标和客服模板。提交品牌方审阅，输出获批版本和联系边界。 |
| 品牌方／产品 | 签核产品事实、双语成稿、预算、测试范围和授权。为所有发布或联系行为分别签核。 |
| Qoder／技术 | 确认接口字段与角色、独立沙盒配置、导入与回执标识、归因缺口评估。由 Qoder 修改其项目文件。 |
| 销售及客服 | 审核后记录询价、意向、跟进与同意，维护门店客户和回填成交。客服回答超出获批知识时转人工。 |

## 对接任务和实际接口

| 业务 | 现有机制 | 可交接的验收标准 |
|---|---|---|
| 环境 | `GET /api/health`，角色会话由 `POST /api/auth/demo` 创建。写入使用同源会话、JSON 与 `X-PurePaw-Request: 1`。 | 先核验 `mode=sandbox`、`outbound=false` 与 `production_ready=false`，使用全新测试库及虚构联系人。此次只读代码和文档。 |
| 内容草稿 | `POST /api/content`，字段有 `channel,title,body,scheduled_at`，可选 `customer_id,simulate_failure`。 | PP-01 至 PP-07 各渠道计划行以内容 ID、版本、渠道做对照。台账记录返回的 MVP 任务 ID。现有接口无外部内容 ID、视频文件、封面或字幕字段。媒体与审批范围留在营销台账。 |
| 审批与模拟 | `POST /api/content/:id/approve` 由管理员把 `draft` 改为 `scheduled`，`GET /api/state` 查看角色范围内状态。 | 沙盒管理员审批会直接排期，后台可自动执行到期任务。获准模拟后再建任务，优先用关闭 worker 的独立环境手动验证 `POST /api/jobs/run`，确认 `external_requests:0`。状态 `simulated` 只记本地结果，正式发布栏留空。 |
| 失败处理 | `retry` 是退避状态，`dead` 是终止。管理员可用 `POST /api/content/:id/retry` 退回草稿。 | 先记录原任务 ID、失败原因与版本，复核同意及内容，重新审批。草稿创建没有调用方幂等键，超时先查台账及角色可见任务，再决定是否重试。 |
| CRM 和同意 | `POST /api/customers` 新建，`PATCH /api/customers/:id` 支持阶段、跟进时间与管理员分配。 `POST /api/customers/:id/consent` 带 `granted,evidence,channel`。 | 客户记录含来源平台、语言、宠物类型。内容 ID 或关键词归因当前人工登记，并关联 CRM 客户 ID。显式填渠道，Telegram 与 WhatsApp 同意独立。创建客户本身无营销同意。 |
| 客服知识 | `POST /api/knowledge` 与 `POST /api/knowledge/:id/approve` 管理 UZ、RU 正文，目前只有产品、价格、库存、配送和合作五种主题。 `POST /api/sandbox/message` 模拟客服，事件 ID 可用于去重。 | 产品、价格、一般合作导入前逐句核对。订单状态、退款、健康和批发承诺走人工核对，模拟自由文本回复提交审批后才进入会话。 |
| 订单与报表 | `POST /api/orders` 建询价，`POST /api/orders/:id/transition` 更新状态，复购可填 `reorder_of`。 | 只选已批准产品。内容、客户与订单通过营销对照表关联。当前 API 无真实平台曝光、广告费和归因接口，先人工导入汇总。 |

## 每日销售报告模板

以塔什干自然日为准，金额用 UZS。按渠道、内容 ID、日期记录；跨渠道总曝光仅为展示次数之和。无数据填“未采集”，零值填写 0。上线前模拟值单列。

| 日期 | 渠道／内容 ID | 发布数 | 曝光／播放 | 新咨询 | 有效线索 | 创建／实付订单 | 实收／退款／净销额 UZS | 广告费 UZS | 首购人数／CAC | 复购人数／复购实收 | 门店新接触／有意向 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 待填 | 待填 | — | — | — | — | — | — | — | — | — | — |

咨询按客户 ID 去重，符合目标服务区、有明确产品需求并可按同意范围继续联系的记为有效线索。实收按支付日期，退款按退款日期。净销额等于实收减退款。CAC 等于归因广告费除以归因首购实付人数，分母为零填“—”。复购按当天再次实付的客户和订单金额统计，复购询价不计。

## 真实运营前待签核

- **产品与货源**。首发 SKU、净重、定版双语标签、配料与喂养说明、适用批次检测、证书的有效期和覆盖范围、可售库存、包材及自有实拍。
- **商业及预算**。成本、零售和批发价、毛利底线、广告预算上限、样品及配送预算、付款、退换、开票和库存补货条件。预算目前留空。
- **账号与许可**。五个公开渠道及 WhatsApp、Telegram 的官方账号与资产角色，渠道审批和测试范围，素材使用授权，客户联系同意和退出机制。令牌交由 Qoder 在受控环境配置。
- **人员**。品牌审批人、产品资料负责人、乌语及俄语校对、内容拍摄剪辑、客服、门店销售和履约对接人，每个岗位指定响应人及时段。
- **技术交接**。按短视频版本变更、草稿未批、跨渠道同意、重复事件及本地任务失败五个场景验收。线上发布、真实客户触达与数据归因各自另行签核。
