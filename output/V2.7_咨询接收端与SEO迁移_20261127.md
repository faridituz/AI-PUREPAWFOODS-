## 一、咨询/招商接收端三方案比较

| 维度 | A：企业邮箱安全服务端表单 | B：授权 CRM HTTPS 接口 | C：官方 WhatsApp / Telegram / 邮箱入口（暂不开表单） |
| --- | --- | --- | --- |
| GoDaddy 兼容 | 高（Linux 主机 PHP + 企业邮箱即可；需确认套餐是否含 SMTP） | 中（纯前端 HTTPS 提交，与主机无关） | 高（纯链接，无后端） |
| 开发成本 | 低（一个 PHP 端点，复用现有前端校验） | 中（需 CRM 字段映射与授权） | 极低（替换表单区为联系方式） |
| 每月费用 | 0（现有主机/邮箱内） | 取决于 CRM；本阶段不新增付费 | 0 |
| 客户信息安全 | 高（服务端接收，前端无密钥；邮件含 PII，需权限与留存策略） | 最高（经批准的加密接口） | 中（PII 在第三方平台，受平台条款约束） |
| 线索丢失风险 | 低（邮件可归档，失败可重试） | 最低 | 高（人工回复，易遗漏） |
| 垃圾信息防护 | 现有蜜罐 + 限流 + 服务端校验；可加验证码 | 同左 + CRM 去重 | 平台自带反垃圾 |
| 重复提交 | 前端幂等 ID + 服务端去重 | 同左 | 无系统去重 |
| 人工跟进效率 | 中（邮箱分派） | 高（CRM 自动分配） | 低（人工切换应用） |
| 后续 CRM 迁移 | 中（邮件导入） | 低（已在 CRM） | 高（历史线索散落） |
| 当前可用性 | 需确认邮箱/主机能力 + 隐私文本 | **未获授权，禁止接入** | **立即可用（已有号码）** |

**推荐：**
1. **立即上线（如不愿等待法律文本与邮箱配置）→ 方案 C**：撤下在线表单，只保留已核实的 WhatsApp `+998 99 987 68 88`、Telegram 与邮箱。零成本、不收集/存储客户信息。
   - 注意：方案 C 会导致上线门禁的 `forms-endpoint` 仍为阻断；要让 C 合法上线，必须由所有者批准调整门禁逻辑（把“无表单 + 明示渠道”视为通过）。**Qoder 不自行放宽门禁。**
2. **正式方案（推荐目标）→ 方案 A**：在 GoDaddy 主机部署一个 HTTPS PHP 接收端点，转发到企业邮箱；保留现有蜜罐、限流、幂等与长度校验；密钥仅存服务端；邮件正文脱敏日志。
   - 前置：确认企业邮箱 SMTP、隐私政策/条款文本、数据留存与删除规则。
3. **方案 B** 仅在所有者书面授权 CRM 与接口凭证后启用；不得使用未授权接口，不得用模拟接口接真实客户。

**通用红线**：不得把邮箱密码、API Key、客户信息写入前端；不得未经批准发送真实消息；模拟提交不得冒充真实线索进入 CRM。

## 三、新站 URL 与迁移映射

当前 `--release` 产物结构为 `/d/{lang}/{page}/`（主题前缀 d）。若最终部署在域名根并去掉 `d`，需所有者批准一次构建路径调整；在批准前，迁移以 `/d/{lang}/` 为准。

| 旧 URL | 新目标（建议 301） | 说明 |
| --- | --- | --- |
| `/` | `/d/uz/`（建议默认语，待所有者确认） | uz/ru 为主要营销语言；若确认 en 为默认则改 `/d/en/` |
| `/sample-page/` | `/d/uz/brand/` | 原占位页，无独立内容 |
| `/hello-world/` | `/d/uz/` | 无博客对应内容 |
| `/category/uncategorized/` | `/d/uz/` | 无分类页对应内容 |
| `/wp-content/uploads/2026/10/purepawlogo.png` | 保留原路径（复制同图） | 避免历史图片链接 404；或 301 到 `/d/assets/logo.png` |
| `/feed/`、`/comments/feed/` | 410（或 301 到首页） | 不是内容页，410 更准确 |
| `/wp-json/*` | 不迁移 | 无 SEO 价值 |

新站规则：

- 每个语言页 canonical **自引用**：`https://<域名>/d/{lang}/...`
- hreflang：8 语互指 + `x-default` 指向默认语言；不存在的语言不得输出。
- sitemap：`/d/sitemap.xml` 包含 104 个内容 URL；robots 声明该 sitemap。
- 语言切换保留当前页面路径（已由前端实现）。
- 404：Apache 的 `ErrorDocument` 无法按路径本地化；建议统一 404 页 + 语言选择，或由 PHP 路由按 `/{lang}/` 输出本地化 404。
- 301 必须在切换当天一次配置，避免链条与回跳；保留查询字符串（当前表单无 GET 参数需求）。
