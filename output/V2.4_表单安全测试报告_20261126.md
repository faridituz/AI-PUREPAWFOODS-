## 二、实现方式（对应 V2.4 要求）

| 要求 | 实现 | 位置 |
| :--- | :--- | :--- |
| 服务端校验 | `validateLead()` 服务端权威校验，客户端仅做前置提示 | `core/validate.mjs` + `serve.mjs` |
| 长度限制 | 姓名 80 / 公司 120 / 电话 32 / 邮箱 120 / 城市 80 / 采购量 80 / 留言 2000；请求体 16 KB | 同上 |
| 恶意输入过滤 | 去首尾空白、控制字符不落库、名称/电话/邮箱脱敏后存储 | `serve.mjs storeLead()` |
| 安全输出 | 成功/错误信息全部为固定文案 + `textContent` 注入，无 `innerHTML`；服务端只返回 JSON | `assets/form.js` |
| XSS | 不回显用户输入；线索文件仅存截断脱敏值 | 同上 |
| CSRF | 校验 Origin 与 Host 一致；无 Cookie 会话；`Sec-Fetch-Site` 兜底 | `serve.mjs sameOrigin()` |
| 限流 | 单 IP 5 次/分钟、30 次/小时，返回 429 + `Retry-After` | `serve.mjs rateLimited()` |
| 反垃圾 | 隐藏蜜罐字段；命中返回假成功不落库 | 同上 |
| 幂等键 | 客户端生成 `request_id`；服务端缓存 2,000 条，重复返回同一结果 | `assets/form.js` + `serve.mjs idemMap` |
| 重复提交处理 | 成功后锁定表单（`data-done`），按钮禁用 | `assets/form.js` |
| 网络超时 | `AbortController` 8 秒超时，提示“连接问题，请重试” | 同上 |
| 提交状态确认 | pending / error / success 三态，`aria-live` 状态区 | 同上 |
| 客户语言记录 | 隐藏字段 lang + 服务端二次记录 | `core/forms.mjs` |
| 营销来源记录 | `source=prototype-a/b/c`；`utm` 从 URL 读取 | 同上 |
| 隐私说明与同意 | 每表单固定隐私说明 + 必勾选，未勾选前后端均拦截 | 同上 |
| 日志脱敏 | 姓名首字+`***`、电话保留前 4 后 2、邮箱首字+`***@域名` | `serve.mjs` |
| 模拟 API 明确标注 | 表单下方固定“本地模拟 API，不进入真实 CRM”；成功提示再次声明 | `core/forms.mjs` |
| 线索失败恢复 | 失败可原地重试（同一幂等键），不丢失已填内容 | `assets/form.js` |

## 三、明确未做 / 未验证

- **未连接真实 CRM**（按要求禁止），因此“真实线索入库/分配/通知”链路未验证。
- **未发送任何真实客户消息**（短信/WhatsApp/邮件均未接）。
- 未接入 CAPTCHA/第三方反垃圾；仅蜜罐 + 限流。
- 超时路径只有代码逻辑，未做真实弱网断网演练。
- 线索失败后的“后台补偿队列”未实现（原型阶段只支持前端重试）。
- 未做渗透测试工具扫描（如 ZAP/Burp）；本报告是功能级安全自测。
- 生产环境还需：WAF/Cloudflare 规则、正式 HTTPS、日志集中化、GDPR/乌兹数据合规审阅。
