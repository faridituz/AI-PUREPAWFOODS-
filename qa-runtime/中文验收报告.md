## 模拟销售链路

本地模拟发布 → 手工录入对应渠道的虚构线索 → 乌语和俄语咨询 → 客服展示演示产品和价格，购买意向转人工 → 从同一 CRM 客户创建询价单并选定产品 → 报价 → 确认并扣减库存 → 演示付款 → 仓库发货与送达 → 创建指向原单的复购询价。

曝光到咨询由测试脚本在界面间人工衔接，系统未采集实际曝光或自动关联社交帖子。客服提供已审核的产品清单，个性化推荐在本次测试中表现为人工按客户需求选定产品。复购验收到关联询价创建。浏览器营销验收选用 Instagram 代表流程，其他平台没有进行真实或逐渠道现场测试。应用的角色选择属于本地演示机制。

## 执行环境与复跑

- Qoder 原有 36 项 Node 测试复跑全部通过，`npm run check` 通过。默认执行沙箱最初拒绝 Node 发起本机回环连接，允许回环后同一套测试全部通过。
- 使用独立目录中的免费 `playwright-core`、已安装的 Windows Edge 和 Node.js v24.22.1。浏览器以 1440 × 1050 桌面视口运行。脚本使用应用原有入口在随机回环端口启动，后台定时 worker 关闭，任务由页面按钮触发。
- 使用新建的临时 SQLite 与密钥，运行后清理。浏览器页面只允许同源回环请求。未接入真实平台、支付、模型或物流服务，没有客户外发、购买服务或修改生产数据。MVP 代码及项目依赖未改动。
- 首跑脚本漏点退出确认框，触发等待超时。已补齐确认动作并加上登出后的 401 断言。最终结果以本目录中的复跑 JSON 为准。

复跑原有测试可在项目目录运行 `npm test` 和 `npm run check`。复跑界面验收可在 `qa-runtime` 运行 `node browser-acceptance.mjs`，前提是本机 Edge 可用且当前执行环境允许回环访问。每次使用全新数据库，输出截图和 [机器结果](evidence/results.json)。[验收脚本](browser-acceptance.mjs)
